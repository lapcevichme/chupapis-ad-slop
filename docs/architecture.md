# Архитектура бэкенда

Перенос из `/Users/laughinme/Code/python/Monolith-backend-template` выполнен.
Сохранены кампании, агент и внешний контракт; перенесены границы слоёв, async-хранение,
Unit of Work, фабрика приложения и наблюдаемость. Источник шаблона — MIT,
уведомление сохранено в `backend/LICENSE.template`.

```text
HTTP → api → service → domain
               ↓
            db / infra
```

| Слой | Ответственность |
|---|---|
| `app/main.py`, `bootstrap.py` | Фабрика, lifespan и сборка зависимостей |
| `api/` | HTTP, DI, схемы ответов, ошибки, SSE-кодирование, OpenAPI и request id |
| `contracts/` | Общие Pydantic-схемы для HTTP и tools; не зависят от транспорта |
| `service/` | Сценарии кампаний/креативов/справочников/чата, аудит, маппинг результатов |
| `domain/` | Правила, роли, enum, ошибки через core, dataclass-представления и события |
| `db/` | ORM, явная загрузка агрегата, UoW и сидирование |
| `infra/` | HTTP-клиент кампаний, LLM/изображения, граф и tools, проверка JSON, CBRO-заглушка |
| `core/` | Настройки, каталог ошибок, доменные исключения и логирование |

Домен не импортирует FastAPI, SQLAlchemy или Pydantic. Сервисы не импортируют API/FastAPI.
API не строит SQL и не возвращает ORM. Между сервисом и HTTP — доменные dataclass и
явное `from_domain`. Общие Pydantic-контракты выделены отдельно, чтобы API и tools
использовали одну схему без зависимости адаптера модели от HTTP-слоя.

## Жизненный цикл и транзакции

`create_app(settings)` не открывает БД и не создаёт клиентов при импорте. Lifespan владеет
async Database, SQLite checkpointer и сервисом чата; закрывает ресурсы при завершении.
Настройки и модели передаются явно, два приложения могут работать с разными БД.

Каждый HTTP-запрос кампании получает один UoW через `Depends(scope="function")`.
Сервисы меняют объект и вызывают `flush`; владелец UoW коммитит **до ответа**, при ошибке
откатывает изменения. Кампания и её аудит записываются вместе. Репозиторий явно загружает
связи кампании; ленивое I/O для агрегата запрещено.

SQLite сохранена, SQLAlchemy работает через aiosqlite. Существующие таблицы и ревизии
`7dc609e004b8 → 0727e0138c95` не заменялись. PostgreSQL в этом этапе не проверялся.
Миграции и сид в Compose выполняет отдельный завершающийся сервис `migrate`, затем
стартует API и после healthcheck — frontend.

## Агент и границы I/O

`service/chat.py` управляет диалогом; граф и инструменты живут в `infra/agent/`.
Сервис отдаёт типизированные события, HTTP-слой превращает их в SSE. Состояние графа
в SQLite checkpointer, связь кампания+логин — в таблице `chat_sessions`.

Агент читает кампании через `infra/campaigns_api.py` по HTTP. На запись получает только
`propose_*`; подтверждённый пакет исполняется контролируемым узлом. LLM, изображения и
HTTP не удерживают транзакцию кампании. Пакет из нескольких запросов **не** является одной
транзакцией; поведение частичного исполнения сохраняется и остаётся отдельным риском.

Модель меняется настройками, промпты — `infra/agent/prompts/`. Генератор изображений
необязателен. Префикс медиа передаётся в валидаторы API и агента из настроек приложения.
CBRO пока локальная успешная заглушка, внешнего побочного эффекта у activate нет.
Outbox/Redis/S3/JWT из шаблона не добавлялись: для них нужен отдельный сценарий.
