# Контекст проекта

**AdPilot AI, SibКод, кейс 1.** По текстовому брифу собрать кампанию с креативом, показать результат и после подтверждения отправить на модерацию. Этот каталог — точка входа для следующего этапа; всё подряд в контекст не загружать.

## Что читать

| Задача | Документы |
|---|---|
| Начать работу | [STATUS.md](STATUS.md), [DECISIONS.md](DECISIONS.md) |
| Понять продукт и границы MVP | [PRODUCT.md](PRODUCT.md) |
| Писать домен/API/агента | Нужный раздел [оригинального задания](../case/Кейс1/task.md), затем [domain.md](domain.md), [architecture.md](architecture.md) |
| Проектировать интерфейс | [PRODUCT.md](PRODUCT.md), [DESIGN.md](DESIGN.md); затем Design Studio |
| Готовить чекпоинт/защиту | [Вопросы](checkpoint-questions.md), [хакатон](research/hackathon.md) |
| Проверить происхождение утверждения | [Источники и пробелы данных](research/sources.md) |
| Решать, что переписывать | [Срез кода и проверок](research/codebase.md), [architecture.md](architecture.md) |
| Менять существующий chat transport | [Действующий chat-api.md](ours/chat-api.md) и OpenAPI |

## Структура и статус

```text
case/                         исходники пользователя, без изменений
docs/PRODUCT.md               сценарии, приоритеты, продуктовая приёмка
docs/DESIGN.md                требования к новому UI; направление ещё не выбрано
docs/domain.md                памятка по инвариантам и контракту
docs/architecture.md          границы реализации и план сравнения шаблонов
docs/DECISIONS.md              решения, допущения и открытые выборы
docs/STATUS.md                 что проверено и что делать следующим
docs/research/                публичные источники, условия хакатона, срез кода
docs/checkpoint-questions.md   только актуальные вопросы
docs/archive/                 старые вопросы и записи ответов ментора
docs/ours/                    унаследованные документы, статус указан ниже
docs/oragnisators/             старые идентичные копии case, для совместимости
docs/dialogs/                 сценарии и сохранённые прежние транскрипты
docs/tools.json               генерируемые схемы текущих инструментов
```

`ours/chat-api.md` сохраняет действующий контракт. `ours/design.md` — справка по текущему фронту; `ours/CONCEPT.md` — ранняя заявка с устаревшим скоупом и недоказанными метриками; `ours/backend-fixes.md` — исторические наблюдения, часть уже исправлена. Они не заменяют новые продуктовые решения. Архивные транскрипты — свидетельство прежнего прогона, не новая приёмка.

## Как поддерживать контекст

Требования не дублировать в нескольких больших файлах: ссылаться на первичный раздел. В AGENTS держать правила и маршруты чтения; в CLAUDE — ссылку на AGENTS. Изменение решения записывать в DECISIONS, результат проверки — в STATUS. Дату, источник, факт/вывод/предположение указывать явно. Новые ответы организаторов закрывают вопросы с записью происхождения.
