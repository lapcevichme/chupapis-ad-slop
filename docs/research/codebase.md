## Известные различия и незакрытые проверки

- **Заголовки:** GET-обработчики допускают отсутствие X-User/X-Role, хотя клиент по заданию передаёт их в каждом запросе. Это явно описано в старом backend README и видно в зависимостях маршрутов.
- **Медиа:** `domain/creatives.py` принимает `/api/media/` наряду с https. Это расширение схемы; совместимость с внешним API требует решения.
- **Восстановленные данные:** оригинальных семи файлов нет; метки и время части записей выбраны командой. Подробности — [sources.md](sources.md).
- **Частичное выполнение:** несколько API-вызовов пакета не являются одной транзакцией. Поведение при падении посередине и рестарте нужно проверить предметно.
- **Качество текста:** в сохранённом [первом транскрипте](../dialogs/transcripts/01-brief-to-moderation.md) агент сам сообщает, что дизайн-агент добавил неподтверждённое условие о фиксации ставки. Это конкретный повод проверить grounding оффера, даже если JSON валиден. Новый живой прогон не выполнялся.
- **Состояние:** тестовый агент использует сценарную модель и InMemorySaver. Сохранение на диске реализовано, но рестарт процесса с ожидающим подтверждением здесь не проверялся.
- **Изображения/LLM:** успех прошлых записей не доказывает доступность сейчас. Старые названия, цены и сравнения моделей в README не проверены внешними источниками.

Старый `ours/backend-fixes.md` содержит исторические наблюдения. Часть уже представлена проходящими тестами: авто-карточка правок, завершение хода после вариантов, обновление PROMO, обработка плохих аргументов tools. Нельзя считать весь документ актуальным списком открытых дефектов.

## Что проверить перед решением о переписи

1. Пользователь передаёт пути шаблонов; проверяем их происхождение и соответствие правилам хакатона.
2. Сравниваем каждый слой по [architecture.md](../architecture.md), фиксируем перенос/перепись без оценки по авторству кода.
3. После изменения запускаем существующие доменные проверки, сборку/линтер и живой основной диалог.
4. Отдельно проверяем рестарт, повтор подтверждения, частичную запись и смену пользователя.
5. Новый UI оцениваем на скриншотах ключевых состояний с настоящими данными; прежний интерфейс не задаёт направление.
