# Правила бэкенда

Архитектура взята из пользовательского Monolith-backend-template. Контракт —
[../docs/CONTRACTS.md](../docs/CONTRACTS.md), карта слоёв — [../docs/architecture.md](../docs/architecture.md).

- `api → service → domain`; `db` и `infra` — адаптеры. API без SQL/ORM, сервисы без FastAPI/API,
  домен без FastAPI/SQLAlchemy/Pydantic. Эти границы проверяет тест.
- `contracts/` — общие Pydantic-схемы HTTP и инструментов; не дублировать их вручную.
  Сервисы возвращают доменные dataclass, API явно преобразует их через `from_domain`.
- Один UoW на HTTP-запрос, `scope="function"`: коммит до ответа. Коммитит только владелец UoW,
  сервисы вызывают `flush()`. Кампания, аудит и событие outbox находятся в одной транзакции.
- `create_app()`/lifespan владеют БД, checkpointer и моделями. Не создавать Settings,
  движки или сетевые клиенты при импорте; передавать настройки явно.
- Вызовы API кампаний, LLM и генерация медиа происходят вне транзакции кампании.
  Внешний побочный эффект (уведомление, выгрузка) идёт через outbox: событие пишется в транзакции,
  обработчик в `service/outbox.py` идемпотентен, доставляет воркер.
- Сохранять существующие operationId, JSON ошибок `{errors: [...]}` и SSE; Problem Details шаблона не берём.
- Права проверяют эндпоинты и сервисы через `Permission` (`domain/users.py`), не названиями ролей.
  Агент ходит в API с токеном пользователя; токен лежит в конфиге графа под ключом `__api_token`
  (ключи с `__` LangGraph не пишет в метаданные чекпоинта).
- ORM остаётся в db/service. Репозиторий кампании загружает агрегат явно, без ленивого I/O.
- Общие схемы креатива и проверки до API применяются и сервером, и агентом.
- Python 3.13, типизация всего app, ruff (100 колонок), mypy --strict. Без шапок-докстрингов
  и описательных комментариев в начале файлов app; комментарии объясняют неочевидную причину.
- Перед коммитом `make check` из корня. После изменения запуска проверить реальный HTTP.
  Тесты идут на настоящих Postgres, Redis и S3 из `docker-compose.test.yml` (порты 5439, 6380, 9002), не используют ключи моделей и рабочую БД.
- Схема — одна начальная ревизия `0001` под PostgreSQL, дальше новые. Тест `test_models_match_migrations`
  падает, если модель изменена без миграции. Данные пользователя не сбрасывать; таблицы чекпоинтов LangGraph
  Alembic не трогает (`include_object`).
