AI-ассистент для менеджера рекламных кампаний в мобильном приложении банка. Менеджер описывает кампанию своими словами, ассистент собирает её целиком: шапку, аудиторию, места показа, баннер, промо-экран и креативы. Перед сохранением он показывает превью. После подтверждения проверяет кампанию и отправляет её на модерацию. Хакатон {Sib}Код, кейс 1.

Слева чат, в центре паспорт кампании, справа превью на телефоне. Каждое изменение в базе происходит только после того, как человек нажмёт «Подтвердить» в карточке.

## Запуск

```bash
cp .env.example .env    # впишите LLM_API_KEY — ключ OpenRouter
docker compose up --build
```

- Интерфейс: http://localhost:5173
- API и Swagger: http://localhost:8000/docs

При первом запуске бэкенд применяет миграции и загружает моки организаторов. Без ключа работают API кампаний и интерфейс, но не чат.

## Как проверить демо

Пользователь переключается в шапке: `ivanov.p` — менеджер, `petrova.m` — модератор.

1. Под менеджером нажмите «Новая» и отправьте бриф из §9 задания: «Кампания по вкладу для клиентов 26–45 в Москве и СПб, промо на главном, ставка 16%, с 5 ноября до конца года».
2. Ассистент подберёт место и сегменты и предупредит, что сегменты складываются по ИЛИ. Время начала и тег он спросит кнопками. Потом предложит сгенерировать картинку.
3. Проверьте превью справа и подтвердите карточку: кампания сохранится черновиком.
4. Нажмите «Отправить на модерацию» и подтвердите отправку.
5. Переключитесь на модератора. У него свой чат по этой кампании. Верните кампанию на правки с комментарием или одобрите.
6. Вернитесь к менеджеру. Комментарий модератора виден в блоке «Ход кампании». Кнопка «Исправить по комментарию» запускает цикл правки, после одобрения доступен «Запустить показ».

Кампании из моков для проверки: 101 и 108 — черновики, 103 — минимальная кампания, 104 — возвращена на правки.

## Архитектура

```text
frontend (React)  ──SSE──▶  /chat  ──▶  LangGraph-агент  ──HTTP──▶  API кампаний (FastAPI)  ──▶  SQLite
                                         │
                                         └─▶ дизайн-агент ─▶ генерация картинок
```

Граф агента:

```text
START → agent ⇄ tools → confirm → agent → … → END
              └──────→ auto_confirm → confirm
```

- **agent** — чат-модель с 36 инструментами: один на каждый вызов API из §3 задания плюс служебные.
- **tools** — выполняет чтение, а пишущие вызовы (`propose_*`) только складывает в пакет и показывает в превью.
- **confirm** — `interrupt()` с пакетом. Это единственный узел, который пишет в API, и только после «Подтвердить». Промптом это не обойти.
- **auto_confirm** — если модель закончила ход с неподтверждёнными правками, карточку показывает сам граф.
- **Дизайн-агент** собирает JSON баннера и промо-экрана. JSON проверяется теми же схемами, что и API, при ошибках до трёх попыток.

Агент ходит в API кампаний по HTTP, а не в базу: адрес задаётся конфигом, поэтому заглушку можно заменить настоящим сервисом. Жизненный цикл, роли и валидация живут на бэкенде, агент их не обходит. Состояние диалогов хранит checkpointer LangGraph, оно переживает перезапуск. У каждой пары «кампания + пользователь» свой диалог. Модели меняются переменными окружения. По умолчанию это Claude Haiku 5.5 для чата, Claude Sonnet 5.5 для дизайна и gpt-image-2.5 для картинок, все через OpenRouter. Кеш промпта и закреплённый провайдер снижают стоимость шага.

Подробно: [backend/README.md](backend/README.md) — бэкенд и агент, [docs/ours/chat-api.md](docs/ours/chat-api.md) — контракт чата.

## Артефакты

- **Промпты:** [chat.md](backend/app/agent/prompts/chat.md) (чат-агент) и [design.md](backend/app/agent/prompts/design.md) (дизайн-агент).
- **JSON-схемы инструментов:** [docs/tools.json](docs/tools.json). Они генерируются из Pydantic-моделей командой `uv run python -m app.export_tools` в `backend/`.
- **Воспроизводимые диалоги:** сценарии в [docs/dialogs](docs/dialogs), транскрипты прогонов в [docs/dialogs/transcripts](docs/dialogs/transcripts). Прогон на живой модели: `uv run python -m app.run_dialogs` в `backend/`. Каждый диалог идёт на свежей БД из моков. Модель недетерминирована, поэтому повтор даёт тот же сценарий, но не дословно тот же текст.
- **Тесты:** `uv run pytest` в `backend/`. Они покрывают валидацию, жизненный цикл, роли, инструменты агента и граф на заготовленных ответах модели.

## Структура

```text
backend/    FastAPI: API кампаний, домен, БД, миграции, агент
frontend/   React: чат, паспорт кампании, превью
docs/       задание, контракт чата, дизайн, диалоги, схемы инструментов
```
